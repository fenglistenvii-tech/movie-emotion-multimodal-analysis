# 运行环境附加组件（ffmpeg / ffprobe）

本仓库的源码不包含 `ffmpeg.exe` 与 `ffprobe.exe`——两个文件合计约 **426 MB**，远超 GitHub
单文件 100 MB 的上限，因此它们作为 **Release 附件**单独分发，见 [RELEASES.md](../RELEASES.md)。

## 一、为什么需要它们

只有 `src/extract_subtitles.py` 需要，其他三个脚本都不依赖 ffmpeg。

| 用途 | 调用方式 | 代码位置 |
| --- | --- | --- |
| 探测 MKV 里有哪些字幕流（索引/编码/语言/标题） | `ffprobe -show_streams -select_streams s` | `analyze_subtitle_streams()` |
| 把选定的字幕流导出为 `.srt` / `.ass` | `ffmpeg -map 0:<index> -c:s copy` | `extract_subtitle_from_mkv()` |

脚本按**当前工作目录**查找这两个文件，找不到时回退到系统 `PATH` 里的 `ffmpeg` / `ffprobe`：

```python
def get_ffmpeg_exe():
    ffmpeg_exe, ffprobe_exe = "ffmpeg", "ffprobe"
    if sys.platform == "win32":
        if os.path.exists("ffmpeg.exe"):  ffmpeg_exe  = "ffmpeg.exe"
        if os.path.exists("ffprobe.exe"): ffprobe_exe = "ffprobe.exe"
    return ffmpeg_exe, ffprobe_exe
```

所以最省事的做法就是：**把两个 exe 放到 `src/` 目录下，然后在 `src/` 里运行脚本。**

## 二、版本信息（随 Release 分发的那一份）

```
ffmpeg  version 2026-03-09-git-9b7439c31b-full_build-www.gyan.dev
ffprobe version 2026-03-09-git-9b7439c31b-full_build-www.gyan.dev
built with gcc 15.2.0 (Rev11, Built by MSYS2 project)
```

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `ffmpeg.exe` | 212.97 MB | full build，静态链接 |
| `ffprobe.exe` | 212.78 MB | 与 ffmpeg 同源，用于流分析 |

构建配置里与本项目相关的部分（来自 `ffmpeg -version` 的 `configuration:` 行）：

```
--enable-gpl --enable-static --enable-fontconfig --enable-libfreetype
--enable-libass --enable-libfribidi --enable-libharfbuzz
--enable-libx264 --enable-libx265 --enable-libvpx --enable-libopus --enable-libmp3lame
```

字幕编解码器支持情况（`ffmpeg -codecs` 实测）：

| 编解码器 | 解码 | 编码 | 本项目用途 |
| --- | --- | --- | --- |
| `subrip` (srt) | ✅ | ✅ | 主要提取目标 |
| `ass` / `ssa` | ✅ | ✅ | 保留特效的原始格式提取 |
| `hdmv_pgs_subtitle` | ✅ | ❌ | 蓝光图片字幕，**只能解码不能转文本**（脚本会拦截并提示 OCR） |
| `dvd_subtitle` | ✅ | ✅ | DVD 图片字幕 |
| `webvtt` / `mov_text` | ✅ | ✅ | 其他文本字幕容器 |

因为是 **full build**，字幕相关的 `libass`、`fontconfig`、`freetype` 都在，不需要额外配置。

## 三、直接使用 Release 附带的那一份

1. 从 Releases 下载打包好的 ffmpeg 附件（`ffmpeg-2026-03-09-full-win64.zip`）；
2. 解压出 `ffmpeg.exe` 与 `ffprobe.exe`，放进仓库的 `src/` 目录；
3. 验证：

   ```powershell
   cd src
   .\ffmpeg.exe -version
   .\ffprobe.exe -version
   ```

   能打印版本号即可用。

## 四、或者自己下载一份

出处：<https://www.gyan.dev/ffmpeg/builds/>

推荐 **`ffmpeg-release-full.7z`**（或 essentials 版，若只处理文本字幕也够用）。
解压后在 `bin/` 目录里能找到 `ffmpeg.exe`、`ffprobe.exe`、`ffplay.exe`，
取前两个放进 `src/` 即可。

也可以让包管理器代劳：

```powershell
winget install Gyan.FFmpeg          # 装完 ffmpeg 就在 PATH 里，无需复制到 src/
scoop install ffmpeg
choco install ffmpeg
```

用包管理器时脚本会自动回退到 `PATH` 里的 ffmpeg，不必再放进 `src/`。

## 五、验证整合是否成功

在 `src/` 目录下执行：

```powershell
python extract_subtitles.py
```

脚本会先打印发现的所有字幕流（形如 `索引:3 | 编码:subrip | 语言:chi`），
再让你输入序号选择要提取的那一条。若看到：

```
❌ 文件不存在: E:\movie\...
```

说明 ffmpeg 已经正常，只是脚本底部硬编码的测试视频路径需要改成你自己的（见 README 第九节第 5 条）。

## 六、注意事项

- **不要**把这两个 exe 提交进仓库。`.gitignore` 已经排除了 `*.exe`，但仍建议不要把它们放进
  仓库目录以外再 `git add -f`。
- 如果原盘的字幕流是 `hdmv_pgs_subtitle`（PGS 图片字幕），ffmpeg 无法直接转成文本，
  脚本会明确提示「⚠️图片格式(需OCR)」并让你改选文本字幕流——这是设计行为，不是缺陷。
- 其余 Python 依赖（OpenCV、MediaPipe、DeepFace、SnowNLP、PyQt5 等）请用
  `pip install -r requirements.txt` 安装，与 ffmpeg 无关。
